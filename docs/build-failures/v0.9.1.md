## #124 macOS AMD64：通用包目标与单架构内核不一致

macOS AMD64 后续在打包阶段失败，直接错误是 `FlClashCore has no arm64 slice (has: x86_64)`。Swift Package Manager 插件支持提示及 Metal 搜索目录 warning 同时出现，但不能替代这条明确的失败证据。固定 Flutter 的 macOS Release 默认要求通用二进制；现有按架构分发矩阵只准备相应 Go 内核，Xcode 的 Core 拷贝守卫因此拒绝缺失 slice。ARM64 任务也需防止同类反向不一致。

`tool/release_pipeline.py` 的正式 package 子进程按公开发行 context 设置 `FLUTTER_XCODE_ARCHS` 为 `x86_64` 或 `arm64`，排除另一架构并禁用 `ONLY_ACTIVE_ARCH`，显式关闭会覆盖 AMD64 选择的 `FLUTTER_MACOS_ARM64_ONLY` 特性开关。Flutter 将 `FLUTTER_XCODE_*` 转成 xcodebuild 设置，两个品牌共用；不改 Xcode 工程文件、不删除 Core slice 守卫、不影响其他平台、不污染父进程环境。CI 与桌面脚本均调用这一入口。

轻量 pipeline 回归 14 项通过，覆盖两个品牌/架构的真实 package 子进程环境、继承错误值覆盖及其他平台保持。VDS 使用固定 Flutter 自有 Platform 类型实际执行 `environmentVariablesAsXcodeBuildSettings`，两架构均输出正确 ARCHS、相反架构 EXCLUDED_ARCHS 和 ONLY_ACTIVE_ARCH=NO；原生 Runner 结果仍须另核对。修复不新增底座接缝；正式验收需从升级分支执行 macOS 对应架构并确认 Sentry 的匹配符号及服务端确认。

## 这次最应改进的安排

把整套Dart打包回归放在x86 VDS的QEMU ARM64环境里执行，成本过高。这不是服务器CPU或内存不足：多次观察仍有资源余量，单个模拟编译/快照阶段无法用多核数量抵消指令模拟成本。

同一SDK生成器，ARM64模拟的build_runner报告593秒，Android所用原生AMD64环境48秒；Linux46项maker回归在模拟环境耗时2543秒，最后发现的是2个测试方法的3个失败子例。应先在正确架构的小型真实用例里发现平台假设，再决定是否执行完整构建，不能让用户反复等完整流程。

本轮已停止这一VDS路线。现有GitHub工作流把Linux ARM64映射到`ubuntu-24.04-arm`并固定Flutter源码revision；保留该正式目标，不因为VDS退役而删除GitHub Linux ARM64支持。本轮没有验证新的GitHub run，不能写成“GitHub已重新构建通过”。GitHub复验必须使用已提交的修复及同步后的SDK/Docs固定引用；既有Jenkins成品仍绑定各自冻结快照，不能因代码入库改标。

Android ARM64不同：JDK/Gradle/NDK在AMD64主机原生运行，再生成ARM64代码，无需模拟ARM操作系统。本次只构建`arm64-v8a`，不产出x86/x86_64 APK。真实Flutter/Gradle编译855.9秒；后续43秒是验收/符号恢复，不是整个APK的编译耗时。

## GitHub #129：Linux ARM64 WebKit 夹具超时

#129 的 Linux ARM64 在正式编译前、冷缓存预检的 linux-maker 阶段失败。48 项测试唯一异常是品牌目录隔离夹具 `xvfb-run -a .../omofly` 超过 15 秒。该测试一次性等待 X server、GTK、WebKit 和退出，stdout 又经管道缓冲，没有阶段证据，不能仅凭超时判定性能不足，也不能证明产品 WebView 挂起。日志里的其他包内容/版本错误是预期负控，不是本次正式包损坏。

本次仅调整自有测试及其正式门禁接线，不改变 `linux/xboard_webview_identity.h`、客户端超时、内核或符号流程，不新增接缝。夹具用 Xvfb `-displayfd` 明确等待服务器就绪（30 秒上限），随后在私有 XDG 目录及独立 `dbus-run-session` 中运行真实品牌程序（60 秒上限），限定 X11 并关闭测试中的辅助功能桥；清除继承的桌面会话地址。两品牌保持真实 GTK/WebKit 数据目录断言，程序立即刷新 gtk_init、webkit_context、manager、complete 标记；退出码非零或缺 complete 均失败，不把打印部分结果视为完成。失败输出包含最后阶段、有限 stdout/stderr；使用普通日志文件避免后代持有管道造成 communicate 等待，复用 stop_tree 清理独立进程组，清理失败同样使测试失败。外层 linux-maker 的 480 秒预算不变。

无 GTK 依赖的回归进入矩阵前共享门禁，也纳入 Linux 冷启动正式命令：受控时钟覆盖延迟就绪/超时、提前退出不冒充就绪；真实父子进程先确认就绪再触发短超时，验证后代清理和阶段日志；成功退出必须有完成标记，失败退出即使有标记也拒绝，清理失败不能吞掉。真实 WebKit 夹具在指定 VDS 预检，Linux ARM64 GitHub 原生 Runner 仍待用户授权全平台构建复验，不将 AMD64 预检等同 ARM64 验收。
