# FlClash v0.8.93 构建失败复盘与排障参考

整理日期：2026-10-23。范围：本项目基于 FlClash v0.8.93 的两个品牌，在现有记录中可追溯的依赖获取、预检、编译、制包、符号上传与发布验证失败。包括早期没有 Actions 序号的批次，以及截至 #115 的已记录事件。

本文是历史经验索引，不替代当前 [DEVELOPMENT](https://github.com/wvjh3z/proxy-suite-docs/blob/main/DEVELOPMENT.md) 的正式入口、版本和操作规则。原始时间线、源码身份、各次测试及真实平台验收边界保留在 [STATUS](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md)，接缝依据保留在 [PATCHES](https://github.com/wvjh3z/proxy-suite-docs/blob/main/PATCHES.md)。没有日志或原始事件的部分明确留作未定结论；不补造缺失运行，不把“所有已记录案例”扩大成“逐条重查过仓库所有历史运行”。

**当前本机已经退役构建环境。本文出现的旧 Flutter、Gradle、Buildkit、Cargokit、子模块目录和本机命令仅用于解释历史，不是重新安装或恢复旧环境的指令。** 后续构建按用户授权在 GitHub 或指定主机执行；新版本 v0.9.1 的失败应独立记录，不混入本历史表。

## 1. 使用方法与证据口径

1. 先找到失败 job 的**第一个真实失败步骤**。`255`、`MSB3073`、`MakeError`、最后一行总异常通常只是包装层。
2. 对照下表定位案例，再看对应类别的“原因 → 修复 → 应保留的验证”。同一错误文字可能来自不同阶段。
3. 比较失败与成功时，同时对齐源码 SHA、品牌、实际构建号、Runner 镜像、工具版本、缓存、入口和工作目录。单有“代码相同”或“本机成功”不够。
4. 用轻量正负控先验证根因，收齐同一批次所有失败后集中修复，再决定必要的正式构建目标。新修改要新建 Run workflow；Re-run 旧记录仍使用旧源码快照。

本文的 `#N` 是 **Actions 运行序号**，不是 APK versionCode 或软件构建号。例如 #115 对应品牌 B 软件 build34；“产品构建24”对应 run39026421452，不能擅自写成 Actions #24。取消、跳过、失败分别记录。

证据层级统一见[ACCEPTANCE](../maintainers/ACCEPTANCE.md)。本历史表中的微型Mach-O、合成ELF、假Flutter、Wine ISCC及Windows原生PowerShell仍只证明对应范围，不能改记为成品/设备通过。

## 3. 入口、依赖、缓存、编码与文件系统

### E1：表单可选字段与解析器强制字段冲突

- **症状**：准备编号阶段退出，平台矩阵未开始；统一错误不足以定位字段。
- **原因与边界**：build_number 是可选输入，旧解析器却要求 inputs 恰好包含全部四键，省略或 null 都失败。原 event 未留存，因此这是已证契约缺陷，不是已确定现场唯一原因。
- **处理**：省略字段使用公开默认值，空/null编号视为未填写，未知字段和非法值仍拒绝。按用户决定移除准备/二次分派链，回到一次 workflow_dispatch。
- **保留验证**：真实事件形态、缺字段/null/非法值、固定 SHA/ref 和 checkout 一致性；不要为显示运行标题引入未经真实验收的分派链。
- **记录**：[D14：本机开发与 GitHub 构建号隔离](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#d14本机开发与-github-构建号隔离)。

### E2：网络下载与 GitHub API 限流

- **#84**：`flutter pub get` 内部 `git clone --mirror yaml_writer` 报 curl56、early EOF、invalid index-pack，pub退出69。依赖此前已存在；SDK lock变化导致新缓存key是间接因素，不是业务代码导致编译错误。
- **#107 Linux AMD64**：APT已完成，AppImage GitHub asset请求报403 rate limit exceeded；不是架构错误，也不能认定Token无效。
- **处理**：pub get仅对已分类网络/超时错误有限重试，历史预算为最多3次、单次300秒、总720秒；认证、配置、代码错误及时停止，取消/超时先清理本次进程树。GitHub API使用现有只读用途Token，重定向到外部资产域名时剥离认证头；保留固定大小/hash校验。
- **验证**：网络失败与确定性失败正负控、真实后代进程清理、限流/重定向边界；不能让编译或打包错误跟着网络重试一起循环。
- **记录**：[2026-10-18 品牌 A #84 macOS Intel 依赖下载失败](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-18-品牌-a-84-macos-intel-依赖下载失败)、[2026-10-19 构建 #107 多平台失败审计与跨平台修复](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-构建-107-多平台失败审计与跨平台修复)。

### E3：完整历史开发机掩盖浅克隆测试错误

- **#76**：测试为了构造错误版本执行 HEAD^1，深度1克隆没有父提交，尚未进入生产版本检查就报错。
- **处理**：在临时仓库用可控种子/commit-tree构造不匹配提交；成功准备仍使用锁定revision。不能靠全量fetch或跳过用例掩盖夹具缺陷。
- **验证**：来源本身也为真实depth1、无全局Git身份，完整/浅历史均测试；原来源HEAD、状态不变。
- **记录**：[2026-10-17 全平台构建 24 失败审计](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-17-全平台构建-24-失败审计)中#76后续段。

### E4：资源摘要与 Git 导出也受换行转换影响

- **#82**：品牌A SVG没有LF，B SVG有LF；Windows autocrlf转换只改变B的字节，manifest校验拒绝。失败Runner原字节未取回，归因由日志、源码和真实Git转换复现共同支持。
- **#107 Windows**：git archive也可能经过工作树转换；只在git apply阶段关autocrlf不够，导出源码已先变CRLF，严格hash正确报Upstream source drift。
- **处理**：摘要保护的品牌资源按原始字节保存；源码导出明确控制Git转换，补丁文本固定LF。不要放宽hash或任意“归一化”二进制成员。
- **验证**：真实Git false/input/true checkout和archive，各品牌实际资源，导出与补丁两端hash；不能只对内存字符串改换行。
- **记录**：[跨平台品牌系统图标](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#跨平台品牌系统图标)、[2026-10-19 构建 #107 多平台失败审计与跨平台修复](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-构建-107-多平台失败审计与跨平台修复)。

### E5：文本协议、子进程输出与负控的跨平台编码

- **#101/#102**：测试默认CP1252解码中文UTF-8 workflow，失败于read_text，尚未编译客户端。
- **相似审计**：Sentry CLI版本输出、PowerShell Get-Content读取中文CMake清单、Android元数据、Linux/Mac清单以及旧Buildkit/Cargokit日志/启动器都有需要显式编码的边界。ASCII输入当前能通过，不等于中文失败已在该CI现场发生。
- **#105 Windows**：旧负控期待主线程抛UnicodeDecodeError，实际异常发生在subprocess读取线程；生产已指定UTF-8，坏的是负控的异常传播假设。
- **处理**：明确UTF-8/BOM/换行协议；诊断流允许容错解码但保留非零退出，结构化成功输出严格校验。负控在主线程对真实原始bytes做错误解码；成功日志在窄代码页下不能反过来使操作失败。
- **验证**：真实子进程、分块中文、非法字节、无换行尾日志、CP1252管道、中文路径；不要仅开PYTHONUTF8环境开关盖住遗漏。
- **记录**：[2026-10-19 Windows 构建 #101/#102 编码失败与接缝精简](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-windows-构建-101102-编码失败与接缝精简)、[2026-10-19 全平台构建 #105 失败审计与修复](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-全平台构建-105-失败审计与修复)、[2026-10-19 构建辅助脚本 UTF-8 与中文路径回归](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-构建辅助脚本-utf-8-与中文路径回归)、[2026-10-19 跨平台构建编码与启动器修复](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-跨平台构建编码与启动器修复)。

### E6：测试自己制造 CRCRLF

- **#103**：Windows检出的模板已经CRLF，测试再将所有LF替换为CRLF，构造出CRCRLF，生产注入器重复执行结果不同。
- **处理**：夹具先将合法CRLF归一为LF，再生成需要的测试换行；不改生产注入器去迎合坏夹具。
- **相邻问题**：此前品牌测试的macOS配置正则只接受LF，也须按实际文本语义解析。
- **验证**：实际Git检出的输入、A/B/A重复注入、无CRCRLF、原checkout不变；恢复旧夹具转换时必须失败。
- **记录**：[2026-10-19 Windows 构建 #103：测试夹具重复 CRLF 转换](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-windows-构建-103测试夹具重复-crlf-转换)、[2026-10-18 Windows 品牌测试 LF／CRLF 兼容（源码修复，待用户CI重试）](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-18-windows-品牌测试-lfcrlf-兼容源码修复待用户ci重试)。

### E7：补丁应用的退出码0不保证全部hunk生效

- **#105**：补丁混用unified/Git头，在父仓库build子目录执行git apply，Git头部分被当作范围外跳过；退出0后输出hash正确拒绝残缺工具。
- **处理**：在独立stage创建无模板临时Git上下文，显式git-dir/work-tree，清除继承Git变量；统一补丁格式并验证每份结果摘要，最后清理元数据。
- **验证**：仓库内外、正式默认输出目录、Git环境污染、重复准备、坏补丁、浅克隆。不要只在仓库外TemporaryDirectory验证，再宣称覆盖正式入口。
- **记录**：[2026-10-19 全平台构建 #105 失败审计与修复](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-全平台构建-105-失败审计与修复)。

### E8：路径别名、盘符与 PowerShell 5.1 语义

- **#105 macOS**：规范化后的物理路径与未经规范化的stage比较，/var等别名被误判越界；先统一比较基准，真实逃逸仍拒绝。
- **#107 Windows**：源码D盘、临时目录C盘，relpath没有合法结果；相对路径夹具放同卷，跨卷用绝对路径另验。
- **#110 Windows**：长路径与8.3短名字符串不同但指向同一目录；PS5.1在某些含方括号父目录下Get-Item缺失条目可返回空集合而不抛错，导致不存在路径被当成功。
- **处理**：按真实目录身份/规范路径验证；PS逐级要求恰好一个目录，最终再次确认存在；CMake同时校验退出码与目录存在，不让成功日志夹杂结构化路径。
- **验证**：原生PS5.1、长短名、中文/空格/特殊字符、缺失叶子/父目录、文件冒充目录、父/嵌套/失效junction、真实CMake调用。Linux PowerShell7不替代PS5.1；#111/#112的Windows已提供后续CI成功证据。
- **记录**：[2026-10-19 全平台构建 #105 失败审计与修复](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-全平台构建-105-失败审计与修复)、[2026-10-19 构建 #107 多平台失败审计与跨平台修复](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-构建-107-多平台失败审计与跨平台修复)、[2026-10-20 构建 #110 Windows Cargokit 路径预检失败与修复](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-20-构建-110-windows-cargokit-路径预检失败与修复)。

### E9：干净 Runner 首次下载不能依赖开发机的 Git 配置

- **#106**：.gitmodules写SSH URL，setup里裸submodule update没有私钥；本地已有HTTPS URL和已初始化源码，因此没暴露。
- **处理**：公开依赖首次获取显式HTTPS、锁定SHA；不要假定独立git命令会继承actions/checkout对子模块URL的处理。
- **验证**：未初始化、空模块缓存、关闭用户/system Git配置、禁止交互、拒绝SSH的负控；再做匿名HTTPS实际获取及后续准备。
- **迁移提醒**：v0.9.1的distributor已改独立源码获取，不应恢复旧distributor子模块；“首次获取必须独立验证”的教训继续适用。
- **记录**：[2026-10-19 构建 #106 子模块初始化失败审计与修复](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-19-构建-106-子模块初始化失败审计与修复)。

### E10：迁移生产者后，消费者仍读取旧缓存

- **#107 Android**：正式激活的是build/packaging-tools副本，产物测试却读取旧plugins/flutter_distributor包图。开发机旧目录存在，CI没有，测试0项执行便报缺依赖。

### S7：服务端处理等待超时，不代表文件从未上传

#115 Windows和两Linux已制包，Sentry CLI约300秒后退出1。留存日志丢了stderr，因此不能唯一断定原因；只读逐ID对账显示25/25、20/20、20/20有服务端记录，其中部分创建晚于CI失败，强烈支持处理等待未及时完成，而不是能证明全部新上传或所有原始错误都已恢复。

处理保留CLI阶段、退出码及安全诊断分类；CLI等待300秒后，对明确“处理中”的结果再做最多600秒逐项只读确认，匹配ID、格式、架构和features。认证失败、真正上传失败、缺项不能吞。仅有artifact元数据不等于保存了完整包/符号；没有文件便不能承诺只补上传。记录：[2026-10-22 GitHub #115 全平台失败定位与修复（正式构建待重试）](https://github.com/wvjh3z/proxy-suite-docs/blob/main/STATUS.md#2026-10-22-github-115-全平台失败定位与修复正式构建待重试)。

## 7. 相邻问题：不要误写成构建失败

| 现象 | 与构建的关系 | 后续参考 |
| --- | --- | --- |
| 安装器运行库检测4005、Start报目录无效 | 包已生成，是安装时工作目录/子进程启动问题；应显式工作目录和准确阶段日志 | DEVELOPMENT的Windows运行库维护及STATUS中安装器记录 |
| 教程WebView的MSVCP140/mtx_do_lock、退出时COM崩溃 | 已安装软件的原生运行故障，不能归为某次CI编译失败 | STATUS对应旧库兼容与退出崩溃记录；新包需设备验证 |
| 中文标题乱码、Logo/字体、数据库被锁、订单异步异常 | 产品功能或编码/数据问题；其修复所带测试可能另有构建阻断，但两者需分开计因 | STATUS对应功能记录 |
| Sentry后台维护401/403 | 维护Token类型/权限，与构建用符号上传Token区分 | DEVELOPMENT的监测配置与Token边界 |
| 沙箱禁止回环、测试缓存目录不可写 | 当前测试环境没执行成功，不是产品测试已失败或已通过 | 在明确授权环境重跑，保留原失败与重跑结果 |

## 8. 后续构建应沿用的做法

| 改动涉及 | 最少应覆盖的真实边界 |
| --- | --- |
| 工作流输入/编号/发布 | 省略与null、源码SHA/ref、失败/取消/跳过、真实Git并发和发布条件；当前源分支回写规则以DEVELOPMENT为准 |
| 依赖或工具初始化 | 无缓存、未初始化、无本机Git重写、无ignored wrapper、固定远端来源和hash |
| 打包器/参数/命名 | 实际锁定解析器与maker、正式默认cwd/output、真实原始文件名到最终清单 |
| 编码/换行/路径 | UTF-8与窄代码页、真实Git三种换行、路径别名/跨盘/8.3/junction、原生PS5.1 |
| 外部进程/超时 | 启动与后代就绪、真实EOF、受控计时、真实回收、失败诊断可留存 |
| Windows安装器 | maker渲染之后的真实ISCC最小预检；实际安装另验，不靠文本断言代替 |
| Sentry符号 | 最终安装包模块与伴随ID/架构匹配、每slice源码证据、上传完成/服务端处理分开、原包与符号一一归档 |
| 跨平台共享修改 | 先跑共享轻量门禁，再做受影响平台专项；不能把POSIX跳过、Linux模拟或一次品牌成功当全部目标通过 |

**为什么以前“稍微改一点就失败”：** 不少改动新增了在正式入口执行的测试，却没有同时覆盖干净Runner、默认目录、原生Shell/编码/文件系统语义；也有依赖生产者迁移后消费者仍读旧缓存，以及过早执行真实工具的顺序问题。静态skill通过只能证明其实际执行的静态范围，不能证明Python/Dart逻辑、外部工具或服务端等待都通过。解决方式是补真实边界与正负控，不是删除门禁，也不是每改一行就重建六个平台。

### 失败后集中处理顺序

1. 收齐当前批次全部失败job及成功对照；先确认是否已生成包、是否已上传符号、是否已发布草稿，避免重复副作用。
2. 保存源码身份、Runner/工具版本、第一处失败、必要诊断及产物/符号摘要，敏感原始日志不提交文档。
3. 建立能复现旧错误的负控；修复后正控通过，其他真实失败仍失败。区分测试问题和生产实现问题。
4. 核对相邻消费者、两个品牌、各目标架构、普通与干净首次入口；补丁/hash、SDK和Docs固定引用一起维护。
5. 先完成与改动相称的检查，再按授权集中构建所需目标。旧源码Re-run不验证新修复，用户取消不计失败。
6. 报告分别列明编译、制包、符号处理、发布和设备验收状态；没有证据的环节继续待验。

### 历史证据与恢复

原记录中的`.toolchains/builds`、`.toolchains/skill-validation`路径是证据索引，不承诺旧工具仍可执行。2026-10-23已删除不再需要的工具/缓存，部分历史符号展开目录改为`.retired.tar.gz`及相邻manifest，临时诊断workflow/运行也有按用户授权删除的记录。先查[当前清理恢复说明](https://github.com/wvjh3z/proxy-suite-docs/blob/main/DEVELOPMENT.md#本机停止构建2026-10-23)；需要历史符号时按匹配批次恢复并核对摘要，不因路径不存在就直接判断“当时没上传”。不要为查旧案例重装v0.8.93环境，不将历史错误原文中的命令直接当当前操作指南。
